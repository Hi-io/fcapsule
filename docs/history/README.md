# Historical Design and Validation Records

These files preserve the development trail for the academic report and future reviews. They describe earlier designs, source revisions or isolated trials. Do not use them as the current operating guide; start with [current documentation](../README.md).

| Record | Why it is retained |

| [Initial concept](initial_concept.md) and [implementation proposal](initial_implementation_proposal.md) | Original research framing, proposed model roles and early development scope; later decisions supersede parts of both. |
| [Operations evolution plan](operations_evolution_plan.md) | Original queue, recurrence and Patterns decisions; its proposed triage strip was later removed. |
| [Product review](product_review.md) | Early operator-first review and checkout prototype observations, including a superseded manual briefing flow. |
| [Product audit](product_audit.md) | Dated UI, storage and documentation audit. |
| [Investigation UX review](ux_investigation_review.md) and [visual design review](visual_design_review.md) | Dated feedback and iteration evidence. |
| [Evaluation record](evaluation_record.md) | Historical model and evidence measurements. |
| [Live validation](live_validation.md) | One controlled Kubernetes integration run. |

The archive is evidence of the project's evolution, not a list of currently qualified claims. For the current product, use [Operations](../operations.md), [AI techniques](../ai_investigation_techniques.md) and [privacy and retention](../data_privacy.md).
