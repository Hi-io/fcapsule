# Capability and Evidence Baseline

This matrix records what the repository can demonstrate through its current automated checks. A test proves the behavior it exercises; it does not establish production reliability or diagnostic correctness outside that case.

| Capability | Tracked evidence | What the evidence supports | Boundary |
|---|---|---|---|
| Case ingestion and capsule creation | `tests/test_control_plane.py`, `tests/test_pipeline.py`, `tests/test_live_sources.py` | Fixture ingestion, bounded source handling, capsule/report generation, and adapter behavior | Adapter tests mostly use fixtures or mocked transports; they do not qualify every live source deployment. |
| Evidence selection and provenance | `tests/test_alert_metric_evidence.py`, `tests/test_context_budget.py`, `tests/test_evidence_service.py`, `tests/ui_evidence.test.cjs`, `tests/ui_references.test.cjs` | Selected observations can retain domain context, bounded references, and report navigation contracts | Valid references do not by themselves prove that an interpretation is factually correct. |
| Retained reports and historical comparison | `tests/test_control_plane.py`, `tests/test_historical_capsules.py`, `tests/test_operations_evolution.py` | A report and useful historical observations remain available after raw inputs expire; regression coverage includes a cold control-plane restart | Retention is subject to configured expiry and available local storage. Historical similarity does not prove a shared cause. |
| Investigation and review boundaries | `tests/test_episode_investigation.py`, `tests/test_atlas_investigation.py`, `tests/test_source_review.py`, `tests/test_historical_grounding.py` | Bounded investigations preserve observations, provenance, uncertainty, and review inputs under tested conditions | Mocked provider responses and rubric checks are not independent confirmation of a successful diagnosis. |
| Operator console contracts | `tests/ui_navigation.test.cjs`, `tests/ui_workspace.test.cjs`, `tests/ui_atlas.test.cjs`, `tests/ui_evidence.test.cjs`, `tests/ui_layout_smoke.test.cjs` | Navigation, retained-record rendering contracts, and selected responsive/accessibility behaviors covered by the DOM suites | The `ui_*.test.cjs` suite is not a live Chrome smoke test. `tests/ui_evidence_smoke.cjs` is a separate opt-in browser check against an instance with retained records. |
| Shared-memory integration | `tests/test_atlas_producer.py`, `tests/test_atlas_ui.py`, `tests/test_atlas_investigation.py` | Tested publication, retrieval, and display behavior for the configured Atlas integration | Does not establish availability or compatibility of an independently hosted service. |
| Install and deployment paths | `.github/workflows/tests.yml`, `tests/test_https_deployment.py`, `tests/test_dependency_discovery.py` | CI runs the Python suite, JavaScript syntax check, and UI DOM suites; deployment helper behavior has targeted tests | A green CI run does not verify a deployed instance. Deployment readiness and live smoke checks remain release steps. |

## Reporting Evaluation Counts

An execution is an attempt, not a successful diagnosis. For example, 100 executions must be reported as 100 attempts unless each outcome has been separately reviewed and meets the diagnosis criteria. Report completed, inconclusive, and failed runs separately, and count diagnostic successes only after applying the stated evidence-grounding and usefulness review. Citation validity, a `ready` status, or an automated rubric score alone is not a diagnosis success. See [`EVALUATION_PLAN.md`](../EVALUATION_PLAN.md) for the qualification gates and threats to validity.
